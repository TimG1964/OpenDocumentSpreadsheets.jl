OpenDocumentSpreadsheets.openods — Function
openods(source; mode="r", enable_cache=true) -> ODSFile
openods(f::Function, source; mode="r", enable_cache=true)

Open an OpenDocument spreadsheet (.ods, .fods or .ots, detected from the content) from a file path or an IO. The do-block form passes the file to f and returns what f returns.

content.xml is read once, and the sheets are located without being parsed.

  • enable_cache=true: a sheet is parsed into memory the first time one of its cells is read; later reads use that copy.
  • enable_cache=false: every read scans the sheet again, keeping nothing, and stops after the last row it needs. Use it with eachrow to stream a large sheet.

Modes, as in XLSX.jl:

  • "r": read only.
  • "rw": read and edit; save with saveods or writeods. Saving patches the original file: everything OpenDocumentSpreadsheets does not edit is kept as it was (D-023).
  • "w": start a new, empty spreadsheet (with one sheet, Sheet1) that will be written to source; an existing file there is not read.

Writing modes need enable_cache=true. With the do-block form, a file opened for writing is saved to source after f returns (not if f throws).

See also readods, newods.

OpenDocumentSpreadsheets.writeods — Function
writeods(dest, xf::ODSFile; overwrite=false, version="1.4") -> path or nothing

Write xf to dest, a file path or an IO.

  • The format follows the extension of a path: .ods, .ots (a template) or .fods (flat XML). Writing to an IO keeps the format the file was read in (.ods for a new one).
  • A file that was read is written by patching it (D-023): what OpenDocumentSpreadsheets does not edit is kept exactly as it was. It can be written as a template or a document, but not converted between zipped and flat XML yet.
  • A new file is written in ODF 1.4, or 1.3 with version="1.3" (D-006).
  • display_text=false leaves out the display text (text:p) of the number, date, time and boolean cells that OpenDocumentSpreadsheets writes; readers recompute it from the value. Files are then smaller (about half, for numeric data) and faster to write (D-029).
  • An existing file at dest is only replaced with overwrite=true.

A path becomes the file's new source (for saveods). Returns the absolute path, or nothing for an IO.

OpenDocumentSpreadsheets.SheetCore.getdata — Function
getdata(sheet, ref)
getdata(sheet, row, column)
getdata(sheet)

Values from a worksheet: a scalar for a single cell, a Matrix{Any} for a rectangular range, or a vector of matrices for a list of ranges. Empty cells, empty strings and errors read as missing.

ref is a cell or range ("A1", "A1:C4", "A:B", "1:4", "A1:A4,C1"), a sheet-qualified one in LibreOffice's or Excel's notation ("Sheet1.A1:C4", "Sheet1!A1:C4"), or a defined name. Indexing a Worksheet calls getdata: sheet["A1"], sheet[1:3, 2], sheet[:].

The value types are described in Cell: Int64 or Float64 for numbers, String, Bool, Date or DateTime, and Time (or a CompoundPeriod for 24 hours or more).

OpenDocumentSpreadsheets.SheetCore.CellRef — Type
CellRef(n::AbstractString)
CellRef(row::Int, col::Int)

A CellRef represents a cell location given by row and column identifiers.

CellRef("B6") indicates a cell located at column 2 and row 6.

These row and column integers can also be passed directly to the CellRef constructor: CellRef(6,2) == CellRef("B6").

Finally, a convenience macro @ref_str is provided: ref"B6" == CellRef("B6").

Examples

cn = SheetCore.CellRef("AB1")
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

cn = SheetCore.CellRef(1, 28)
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

cn = SheetCore.ref"AB1"
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

OpenDocumentSpreadsheets.SheetCellRef — Type
SheetCellRef{S<:RefStyle}(ref::AbstractString)
SheetCellRef{S<:RefStyle}(sheet::AbstractString, cellref::CellRef)

A cell on a named sheet: a CellRef together with the name of its sheet, in the fields sheet and cellref. S is the notation it is parsed from and shown in (RefStyle); each back end binds SheetCellRef to its own style.

SheetCellRef{ExcelStyle}("Sheet1!B2") refers to cell B2 on sheet Sheet1. A sheet name containing spaces or other special characters is quoted, as in Excel: SheetCellRef{ExcelStyle}("'Sheet 1'!B2"), which SheetCellRef{ExcelStyle}("Sheet 1", CellRef("B2")) also gives. julia> SheetCore.SheetCellRef{SheetCore.ODFStyle}("'My sheet'.B2")

julia> r.sheet
"Sheet1"

julia> r.cellref
B2

OpenDocumentSpreadsheets.readtable — Function
readtable(source, [sheet, [columns]]; [first_row], [column_labels], [header],
          [infer_eltypes], [stop_in_empty_row], [stop_in_row_function],
          [keep_empty_rows], [normalizenames], [missing_strings]) -> DataTable

Read a table from a file path or IO without keeping the sheet in memory: gettable on sheet (a name or number; the first sheet if not given) of the file opened with enable_cache=false.

Use first_row to give the first row of the table (its header, if header=true). Without it, the table starts at the first row with data in its first column.

header (default true) says whether the first row holds the column labels. Without a header, and without column_labels, the labels are the column letters.

column_labels gives the labels as a vector of Symbols or strings.

normalizenames=true turns the labels into valid Julia identifiers.

missing_strings gives strings (one, or a vector) to read as missing.

infer_eltypes (default true) gives each column the narrowest element type of its values; otherwise columns are Vector{Any}.

stop_in_empty_row (default true) ends the table at the first empty row. stop_in_row_function is a function of a TableRow returning true at the row that ends the table (that row is left out).

keep_empty_rows (default false) keeps rows whose values are all missing between the first and the last row of the table.

enable_cache is accepted for compatibility with XLSX.jl and ignored.

OpenDocumentSpreadsheets.setdata! — Function
setdata!(sheet, ref, value)
setdata!(sheet, row, col, value)
sheet[ref] = value
sheet[row, col] = value

Write value into a cell, or into every cell of a range. The file must be writable (openods with mode="rw" or "w", or newods).

  • value may be a number, string, Bool, Date, DateTime, Time, a period (a duration), or missing/nothing to empty the cell.
  • A matrix fills a range of its size.
  • A vector fills a row (dim=2, the default) or a column (dim=1) from a cell, or a one-row or one-column range.
  • ref takes the forms of getdata: "B2", "B2:D4", "Sheet1.B2", "Sheet1!B2", integers and ranges, or a defined name that refers to cells on the sheet.
  • With : for the rows or columns, as in XLSX.jl: ws[3, :] = [1, 2, 3] writes a vector along row 3 from column A, and ws[:, 2] = v down column B from row 1. Any other value fills the cells addressed, where : stands for the sheet's used columns or rows (ws[3, :] = 0, ws[:, 2:3] = missing, ws[:] = 1).

A cell keeps its style when that style's format fits the new value. Otherwise dates, date-times, times and booleans get ISO formats, and numbers and text the Default style (D-024, D-027).

Rows and columns

Inserting and deleting rows and columns moves every reference to them as LibreOffice moves it: formulas on every sheet, defined names, merges, conditional formats, validations, database ranges, print ranges, charts and anchored shapes.

OpenDocumentSpreadsheets.insertRows — Function
insertRows(sheet, at; count = 1)
insertRows(xf, "Sheet1.5"; count = 1)

Insert count empty rows before row at (an integer, or a string such as "5"). The rows from at down move down, and everything that refers to them follows, as in LibreOffice: formulas on every sheet, defined names, merged cells, conditional formats, validations, database ranges, print ranges, charts and anchored shapes. A range that the new rows fall inside, or whose last row is at at, grows (D-050).

The new rows take the cell formats of the row above, and its height when that height was set, and are not hidden (D-051). Inserting at row 1 gives unformatted rows. An insert that would push a cell with content or formatting off the sheet is an error, as it is in LibreOffice (D-052).

OpenDocumentSpreadsheets.deleteRows — Function
deleteRows(sheet, rows)

Delete rows: an integer, a range, a vector of row numbers, or a string ("3", "3:5", "3:5,9" or "3:5~9"; a cell or range gives its rows, a defined name its range's rows). The rows below move up, and everything that refers to them follows, as in LibreOffice (D-050): a reference to a deleted cell becomes #REF!, and a range that loses some of its rows shrinks. Defined names

Named ranges and named expressions, the file's own and each sheet's. They follow LibreOffice's rules for names and are stored as LibreOffice stores them.

OpenDocumentSpreadsheets.addDefinedName — Function
addDefinedName(xf::ODSFile, name, value; absolute=true)
addDefinedName(sheet::Worksheet, name, value; absolute=true)

Add a defined name to the file, or to a sheet (a name only that sheet's formulas see). value can be:

  • a reference: a SheetCellRef, SheetCellRange, SheetColumnRange, SheetRowRange or NonContiguousRange, or a string such as "Sheet1.A1:B2", "Sheet1!A1:B2" or "Sheet1.A1:A3,Sheet1.C1". A sheet's name may leave the sheet out ("A1:B2", "A1,C3", "A:C"); a file's name may not.
  • a number, a Bool or any other string: a constant
  • a string starting with =: a formula, in LibreOffice's notation ("=SUM($Sheet1.$A$1:$A$9)*2"). As in LibreOffice, its references are relative to A1 of the file's first sheet (or of the sheet, for a sheet's name) unless they have $, the sheet's name included: Sheet1.A1 used on the next sheet refers to that sheet's A1.

absolute=false makes a reference relative (A1 rather than $A$1): as in LibreOffice, a formula using the name then refers to the cells at the same offset from its own cell as the reference is from A1. Its sheet stays the one named. Give a vector, one entry per area, for a NonContiguousRange.

Names follow LibreOffice's rules (F-050): a letter or _ first, then letters, digits, _ and ?, and nothing that reads as a cell reference (A1, R1C1, R, C1x). They are unique without regard to case within a file, or within a sheet; a sheet's name may be the same as a file's name, and then hides it on that sheet.

Examples

addDefinedName(xf, "Prices", "Data.B2:B20")
addDefinedName(xf["Data"], "Rate", 0.2)
addDefinedName(xf, "Total", "=SUM(Data.B2:B20)")

OpenDocumentSpreadsheets.setFormat — Function
setFormat(sheet, ref; format) -> String or -1
setFormat(sheet, row, col; format)
setFormat(xf, "Sheet1.A1:B2"; format)

Set the number format of cells (address forms as setFont). format is:

  • a built-in name: "General", "Number" (0.00), "Currency", "Percentage" (0%), "ShortDate" (m/d/yyyy), "LongDate" (d-mmm-yy), "Time" (h:mm:ss), "Scientific" (##0.0E+0);

The shared core

The format-independent parts of OpenDocumentSpreadsheets (references, tables, number formats, dates) live in a submodule meant to be shared with XLSX.jl in future. It is not part of the public API.

OpenDocumentSpreadsheets.SheetCore — Module
SheetCore

The format-independent core shared by the spreadsheet back ends (D-001): cell references and ranges, tabular data and Tables.jl input, number formats and displayed text, date serial numbers, text widths for autofit, colours, and reading zip parts.

It knows nothing about ODF or OOXML. It is developed inside OpenDocumentSpreadsheets.jl, and is kept self-contained so that it can later become a package of its own that XLSX.jl can also use (see records/core-migration.md in the workspace). Most of its code is adapted from XLSX.jl 0.13.4 (MIT License, Copyright (c) 2018-2026 Felipe Noronha Tavares and other contributors); each file says what it came from and what changed.

Its names are the ones XLSX.jl uses, so that adopting it is a matter of imports.
