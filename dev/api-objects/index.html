API reference: links, notes and objects

Hyperlinks, notes and threaded comments, pictures, data validation, tables, AutoFilters and sorting (phase 6). Links, notes, pictures and tables introduces them.

Hyperlinks

LibreOffice's two kinds of link: a URL field in a cell's text, and a cell link in its style (F-058):

OpenDocumentSpreadsheets.addHyperlink — Function
addHyperlink(sheet, ref; url=nothing, location=nothing, display=nothing) -> NamedTuple
addHyperlink(sheet, row, col; kw...) -> NamedTuple

Make a cell, or each cell of a range ("A1:C3"), a hyperlink, as LibreOffice's import of XLSX.jl's links does (F-058, D-072). Give exactly one of:

  • url: an address outside the workbook ("https://julialang.org", "mailto:team@example.com"), or a file relative to the document's folder ("report.pdf")
  • location: a place in the workbook: a cell or range ("Sheet2.A1" or XLSX.jl's "Sheet2!A1", "'My Sheet'.C3"), a sheet, or a defined name

LibreOffice has two kinds of link. An empty cell, or a text cell, gets a URL field around its text: an empty cell takes display (or url, or location) as its text, and a text cell keeps its text. A number, a formula, and every cell of a range after the first get a cell link: their value is unchanged, and a click on the cell follows it. A cell's previous links are replaced. Writing a new value into a cell drops its URL field, as in LibreOffice; its cell link stays.

A URL is kept as LibreOffice keeps it once loaded (F-065): its scheme in lower case, and for http, https and ftp a / after a host with no path and spaces as %20 ("https://julialang.org" becomes "https://julialang.org/"). A relative file is written as the file's format needs it: ../report.pdf in a zipped .ods, whose links are relative to the package, and report.pdf in a flat .fods.

LibreOffice has no tooltips: tooltip is an error.

Returns the link of the first cell, as getHyperlink reads it. The file must be writable.

Notes and threaded comments

LibreOffice's annotations, and the threaded comments it keeps inside them (F-059):

OpenDocumentSpreadsheets.addComment — Function
addComment(sheet, ref, text; author="", width=144, height=79, visible=false, date=now) -> NamedTuple
addComment(sheet, row, col, text; kw...) -> NamedTuple

Attach a note (LibreOffice's comment, an annotation) to one cell, replacing any it has (F-059, D-073). text may hold line breaks (\n). author is shown with the note; width and height are its size in pixels (LibreOffice sizes a note's width from its text, and takes the height as a minimum); visible=true shows it always, not only when the mouse is over the cell. A cell with a threaded comment is refused.

date (a Date or DateTime; the time of the call, in UTC, if not given) is LibreOffice's own (D-076): it shows a note's date with its author.

Returns (sheet, ref, author, text, date). The file must be writable.

Pictures

Pictures anchored in cells, resizing with them, as LibreOffice's import places XLSX.jl's (F-060):

OpenDocumentSpreadsheets.addImage — Function
addImage(sheet, ref, image; size=nothing, inCell=false, alt="", description="") -> NamedTuple
addImage(sheet, row, col, image; kw...) -> NamedTuple

Insert a picture (PNG, JPEG or GIF, from a file path or an IOBuffer, which is left unchanged) over the cells from ref, as LibreOffice's import places XLSX.jl's (F-060, D-074): anchored in the first cell and resizing with its cells up to the last. For a cell, the picture covers one cell per 64 pixels of its width and per 20 of its height (its own size, or size = (width, height) in pixels), as in XLSX.jl; for a range ("B2:D6"), the range. The picture is stored once in the file, however many times it is shown.

LibreOffice has no pictures in cells: inCell=true is an error. alt is the picture's alt text, which LibreOffice keeps for every picture (its Text Alternative, svg:title), and description its longer description (svg:desc), LibreOffice's own (D-076).

Returns (sheet, media_name, from, to, alt, description). The file must be writable.

The pictures of a sheet, or of every sheet, as (sheet, media_name, from, to, alt, description), by their first cell: those anchored in cells or to the page, read from the file or added. to is the cell a picture ends in. media_name is its part's name in Pictures/ ("" for a picture held in a flat file).

Data validation

The rules of LibreOffice's Data ▸ Validity, stored as its import stores XLSX.jl's (F-061, F-068):

OpenDocumentSpreadsheets.addDataValidation — Function
addDataValidation(sheet, rng; type, operator, formula1, formula2, values, allowBlank=true, dropdown,
                  showInputMessage=true, promptTitle, prompt, showErrorMessage=true, errorTitle, error,
                  errorStyle=:stop, caseSensitive=false, sortEntries=false) -> NamedTuple
addDataValidation(xf, "Sheet1.B2:B20"; kw...)

Restrict what may be typed into the cells of rng (a cell, range, whole columns "B:B" or rows, a list of ranges "A1:A5,C1:C5", or a defined name), as LibreOffice's Data ▸ Validity does, stored as LibreOffice's import stores XLSX.jl's validations (F-061, D-075).

type is :list, :whole, :decimal, :date, :time, :textLength, :custom or :any (:list when values is given). For the number, date, time and length types, operator is :between (the default), :notBetween, :equal, :notEqual, :greaterThan, :lessThan, :greaterThanOrEqual or :lessThanOrEqual, with formula1 (and formula2 for the two between forms). formula1 and formula2 are numbers, a Date, Time or DateTime, or a reference or formula in LibreOffice's notation ("$D$1:$D$3", "Lists.$A$1:$A$9", or XLSX.jl's "Lists!$A$1:$A$9"; "=ISNUMBER(B2)"). A list's items may be given as values.

allowBlank, dropdown (a list's drop-down), showInputMessage with prompt and promptTitle, and showErrorMessage with error, errorTitle and errorStyle (:stop, :warning, :information) are as in XLSX.jl. As in LibreOffice, a cell has one validation: a new one replaces the validation of the cells it covers. Identical validations share one rule.

Two options are LibreOffice's own, with no XLSX.jl counterpart (D-076): caseSensitive (table:case-sensitive: lists and comparisons with text tell upper and lower case apart) and sortEntries (a :list's drop-down shows its items sorted ascending).

Returns the validation, as getDataValidation reads it. An :any validation without a prompt or error message restricts nothing, and LibreOffice stores none: it removes the validation of its cells, and nothing is returned. The file must be writable.

Tables

Tables are LibreOffice's database ranges (Data ▸ Define Range), stored as its import stores XLSX.jl's tables (F-062, F-070). LibreOffice has no table styles, and keeps no totals settings: they are read from the totals cells' formulas.

OpenDocumentSpreadsheets.Table — Type
Table

A table: a named range of a sheet whose first row holds the column labels (LibreOffice's database range, Data ▸ Define Range; an Excel table in XLSX.jl). Obtain one with table or tables, make one with addtable!. A Table is a Tables.jl table of its data rows (DataFrame(t)), as gettable reads them.

Fields

  • id::Int: its number among the workbook's tables, in the file's order (LibreOffice has no ids: deleting a table renumbers those after it)
  • name::String: its name, unique in the workbook ignoring case; display_name is the same
  • ref::CellRange: its cells, with the header row and any totals row
  • columns::Vector{String}: the column labels, from the header row ("Column B" for an empty one, and for every column of a table without a header, as LibreOffice names them)
  • has_header_row::Bool: whether the first row holds the labels (LibreOffice's Contains column labels)
  • has_totals_row::Bool: whether the last row holds the totals (Contains totals row)
  • style: always nothing (LibreOffice has no table styles)
  • sheet: the Worksheet
  • filterButtons::Bool: whether the header shows filter buttons (LibreOffice's, D-076)

A Table is a snapshot: the functions that change a table return a new one.

OpenDocumentSpreadsheets.addtable! — Function
addtable!(sheet, ref; name="", style=nothing, has_totals_row=false, has_header_row=true,
          filterButtons=true) -> Table

Make the cells ref ("A1:C10") a table, as LibreOffice's Data ▸ Define Range makes a database range, stored as LibreOffice's import stores XLSX.jl's tables (F-062, D-077). The cells are not changed: the first row must already hold the column labels, each given and none repeated (ignoring case), as in XLSX.jl.

name is LibreOffice's: formed as a defined name's, and unique among the workbook's tables ignoring case (it may be a defined name's too, as LibreOffice allows); "" gives the first free TableN. has_totals_row=true makes the last row the totals row (see settotals!); its cells are left as they are. LibreOffice has no table styles: style other than nothing or "None" is an error.

LibreOffice's own options (D-076): has_header_row=false makes a table whose first row is data (its columns are then named "Column A", …), and filterButtons=false hides the header's filter buttons, which a table shows by default, as LibreOffice's import gives Excel's.

As in LibreOffice, tables may overlap each other and merged cells, and a table may be its header row alone. The file must be writable.

AutoFilters

A sheet's AutoFilter is LibreOffice's anonymous database range of the sheet, with filter buttons (F-062). Its criteria are stored as LibreOffice stores them, and rows are hidden as LibreOffice's Refresh Range hides them (F-071); a sort puts the rows in LibreOffice's order and moves what LibreOffice's Data ▸ Sort moves (F-072). Both differ from Excel in places: see setAutoFilter.

OpenDocumentSpreadsheets.setAutoFilter — Function
setAutoFilter(sheet, rng; filters=nothing, sort=nothing, caseSensitive=false, noDuplicates=false,
              naturalSort=false, includeFormats=true)
setAutoFilter(xf, "Sheet1.A1:D20"; kw...)

Add filter buttons to the first row of rng, as LibreOffice's Data ▸ AutoFilter does, stored as LibreOffice stores a sheet's AutoFilter: the sheet's anonymous database range (F-062, D-078). rng is a range of cells ("A1:D20"), a defined name, or : for the sheet's used range. Its first row is the header row.

A sheet has one AutoFilter, so this replaces any the sheet has. It may not overlap a table (see addtable!). Setting the filter again on the same range keeps its criteria and sort, unless new ones are given. With both, the rows are sorted first and then filtered, as LibreOffice does.

Filtering

filters gives criteria for some of the columns, as pairs of a column and a criterion. A column is given by its header text, its column letter or its position in the range (1 for the first). Rows a criterion doesn't show are hidden (as LibreOffice hides them, table:visibility="filter") and the others shown, so the file opens filtered, as LibreOffice would have saved it. A row is shown if it meets the criteria of every filtered column. A criterion is one of:

  • a value, or a vector of values, to show: text (in any case), numbers, dates, true/false, and missing for empty cells.
  • a condition, op => value, where op is "==", "!=", ">", ">=", "<" or "<=" and value a number, a date or text. With "==" and "!=", text may use Excel's wildcards: * for any characters, ? for any one, and ~ before one of them for itself. "!=" => "" shows the cells that aren't empty.
  • two conditions joined by :and or :or: (">=" => 10, :and, "<" => 20).
  • (:top, n) or (:bottom, n) for the n largest or smallest numbers, or (:top, n, :percent) and (:bottom, n, :percent) for a percentage of the cells.
  • a regular expression, r"^a.*z$" or "!=" => r"…" (LibreOffice's own; it must match the whole cell's text).

Criteria are applied as LibreOffice's Refresh Range applies them (F-071), which differs from Excel:

  • Text that LibreOffice reads as a number ("10", "1,000", "(1)", "2026-11-23 15:00") is compared with numbers as that number, and with text as text; other text is compared with the text a number shows ("50%", "TRUE"). A number is compared only with numbers.
  • Values in a list are compared as such text, so [10] shows the text "10" too, and a date shows cells of that date at midnight, not later that day.
  • A ranking counts every cell that isn't empty, and sorts text and errors above the largest numbers.
  • "!=" => "" treats a formula giving "" as empty, while missing shows only cells holding nothing.

LibreOffice has no above- or below-average or relative-date filters (:aboveAverage, :today, :Q1, …): they are errors.

LibreOffice's own options (D-076): caseSensitive=true compares text in its case, and noDuplicates=true hides rows that show the same as a row above them (always comparing case), as LibreOffice's No duplications. noDuplicates applies to the criteria given, so it needs filters, and LibreOffice applies it only with at least one criterion.

filters=[] removes the criteria and shows every row of the range.

Sorting

sort gives a column, column => :ascending or column => :descending, or a vector of these, the first sorting first. The rows below the header are put in that order, as LibreOffice's Data ▸ Sort puts them (F-072, D-079), and the sort is stored with the range:

  • ascending: numbers and dates, with FALSE and TRUE as 0 and 1; then text, in LibreOffice's alphabetical order (ignoring case, and accents but where they alone differ); then errors. Descending reverses this. Empty cells are last either way, and rows that compare equal keep their order.
  • each row's cells in the range move with their formats, validations, notes, links and pictures, and its hidden state goes with it; a formula moves as if copied, so =B5*2 in row 5 becomes =B2*2 in row 2, and is saved without a value (LibreOffice computes it on loading). Cells outside the range's columns, row heights, and formulas and names that refer to the sorted cells stay as they are, as in LibreOffice.
  • a range with merged cells is refused (LibreOffice sorts it only without formats), and so is one with an array formula.

LibreOffice's own options (D-076): caseSensitive=true (shared with the criteria) puts lower case before upper case where text is otherwise equal; naturalSort=true compares the numbers within text by value ("a2" before "a10"); includeFormats=false leaves the formats and validations where they are and moves only the values, notes, links and pictures (which allows merged cells).

The file must be writable.

Examples

julia> setAutoFilter(sheet, "A1:F200")

julia> setAutoFilter(sheet, :)

julia> setAutoFilter(sheet, "A1:D50"; filters = ["Colour" => ["Red", "Blue"], "Amount" => (">" => 100)],
                     sort = "Amount" => :descending)

See also getAutoFilter and removeAutoFilter.
